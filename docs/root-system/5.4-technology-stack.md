### 1\. Overview

**The stack is LOCKED.** Nothing new enters it without a logged ADR in 5.3, approved by Omegea Hunter. "It would be easier with X" is not an argument; an ADR is.

The stack is chosen against one deliberate trade-off (ADR-0006): **robust and cheap, sacrificing fast.** Free-tier by default. A second hosted server is a cost, not a convenience — that is the reasoning that removed Payload CMS.

### 3\. Tech Radar

**Rings:** **Adopt** (proven, default) · **Trial** (worth pursuing) · **Assess** (explore, not committed) · **Hold** (avoid new use) · **Deprecate** (actively removing).

#### 3.1 Adopt

| Technology | Quadrant | Rationale |
| ---| ---| --- |
| Expo / React Native | Languages & Frameworks | iOS reliability for push, real biometrics, real offline — a PWA can't deliver these (ADR-0001) |
| Supabase | Platforms & Infrastructure | Postgres + RLS + Auth + Storage + Realtime + Edge Functions + pg\_cron in one sovereign, exportable, free-tier service (ADR-0002) |
| Postgres generated columns & views | Data & Techniques | The mechanism that kills the Notion chained-formula problem — the anti-Notion rule |
| RLS as authorization | Data & Techniques | Tenancy enforced at the data layer, not in application code (ADR-0004) |
| TanStack Query + expo-sqlite | Languages & Frameworks | Offline persistence and optimistic writes without hand-rolling a sync engine |
| Zod | Languages & Frameworks | One validation definition shared across form, client, and function boundaries |
| EAS Build + Update | Tools | Cloud builds and OTA remove the local-Mac constraint entirely |
| Sentry | Tools | Client and function error visibility for a solo operator who can't watch logs live |

#### 3.2 Trial

| Technology | Quadrant | Exit criteria |
| ---| ---| --- |
| Victory Native | Languages & Frameworks | Keeps if it renders the Command Center rollups at target frame rates; otherwise reassess before Phase 4 |

#### 3.3 Assess

| Technology | Quadrant | Why interesting | Open questions |
| ---| ---| ---| --- |
| React Native Web | Platforms | A web companion for free from the same code | Does the hub layout survive a desktop viewport? Phase 7. |
| Stripe / RevenueCat | Platforms | Required for a commercial Freelance Life OS tenant | Which one; only after the Phase 7 go decision |
| AI insights layer | Data & Techniques | Energy prediction, trade patterns, habit/mood correlations | Phase 7; needs real logged data first |
| Local-first sync | Data & Techniques | Full offline-write across all hubs | Only if last-write-wins proves insufficient |

#### 3.4 Hold

| Technology | Quadrant | Why on hold |
| ---| ---| --- |
| [Make.com](http://Make.com) | Tools | No [Make.com](http://Make.com) inside the app. Automation is Edge Functions + pg\_cron. Make stays a UJG business-ops tool, not an app dependency. |
| Next.js PWA | Languages & Frameworks | Rejected in ADR-0001 — cannot deliver push, biometrics, or offline reliably |
| Firebase | Platforms | Document model is wrong for relational computation |
| Bank / Plaid auto-sync | Platforms | Out of scope for v1 — manual entry plus recurring rules first |
| New state libraries | Languages & Frameworks | TanStack Query + Zustand is the answer. Adding another needs an ADR. |

#### 3.5 Deprecate

| Technology | Replacement | Status |
| ---| ---| --- |
| Payload CMS | In-app editors + Supabase Studio | Removed per ADR-0003. A second server to host, auth, and maintain for a tiny payoff; removing it also removed the two-writers risk. `/payload` is out of the repo layout and the `cms_*` prefix is retired. |
| Notion (as the daily engine) | This application | Retired from daily operation at the Phase 6 cutover; kept as archive only |

### 4\. Selection Rationale & Trade-offs

| Choice | Alternatives considered | Deciding factors | ADR |
| ---| ---| ---| --- |
| Expo (native) | Next.js PWA | Push reliability, real biometrics, real offline | ADR-0001 |
| Supabase | Hand-rolled Node/Postgres · Firebase | One sovereign free-tier service; Postgres relations and generated columns; great for solo + agentic builds | ADR-0002 |
| Drop Payload CMS | Keep it for a content admin UI | Second server, tiny payoff, two-writers risk | ADR-0003 |
| Three-layer tenancy | Single-user, retrofit later | Retrofitting tenancy is a rewrite | ADR-0004 |
| Shared action-spine | Per-hub siloed data | Silos can't show whole-life control or drive cross-hub action | ADR-0005 |

### 6\. Governance & Change Process

To add or move a technology: write an ADR in 5.3 stating context, options, decision, and consequences. Omegea Hunter approves. Record the ring change in §7. **No technology enters the codebase before its ADR exists** — not after, not "we'll document it later."
