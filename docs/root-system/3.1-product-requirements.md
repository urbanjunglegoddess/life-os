### 1\. Executive Summary / Overview

A **multi-tenant personal + freelance life OS** that shows the control of someone's life and **drives daily action** — money, time, work, wellness, home, academics, and family in one cockpit.

It fuses **Monarch** (automated money and control), **Notion** (linked databases and knowledge), and **Calendar** (time as the axis) into a single owned application.

> **A website tells; an application does.** This is a thing that does, not a thing that tells. Every plan, goal, bill, routine, and ritual decomposes into **Actions** carrying a do-now deep link. Progress rolls up from completed Actions — it is never typed by hand.

### 2\. Problem Statement & Background

*   **Requirement (WHAT, not HOW):** a single owned application that runs a person's entire personal and freelance life — money, calendar, work, wellness, home, academics, family — as one connected system **that drives action**.
*   **Problem:** the Notion Command Center is the right system on the wrong engine. Formulas can't chain, automation isn't real, mobile capture is slow, there's no biometric privacy, recipes and measurements are weak, and it all rents on someone else's platform. **The result holds plans but makes nothing happen.**
*   **Why now:** without the build, daily operation stays high-friction and nothing executes on its own.
*   **Strategic alignment:** sovereignty and automation — the operator layer beneath every Empire Holding / UJG / JMR activity, and the engine for a sellable Freelance Life OS.

### 6\. Product Structure — Hubs Over a Shared Spine

The app is **one record, many views**. Hubs are lenses over a shared core, not silos. Full map in 4.1.

#### 6.0 The spine (inherited by every hub)

Actions · Events · Money ledger · People/CRM · Goals & Missions · Notes stream · Areas/Tags taxonomy · Automation + Notifications · Templates/Routines.

#### 6.1 Command Center — platform surface `UJGFREE-5896`

The cockpit. Owns almost nothing: the **Today snapshot** and the **quick-capture inbox**. Absorbs at-a-glance Reports/rollups. Reads everything.

*   **CORE:** today's date, greeting, rotating affirmation; Today's Journal card; Today's Focus (tasks, assignments, projects due); Today's Missions; Schedule; summary strip (habits done/total, net cash today, sessions logged); quick-add (task, journal line, habit check, expense, time block); do-now deep links on every Action.
*   **LATER** **`FUTURE-STATE`****:** reorderable widgets; energy check-in that biases what surfaces.

### 7\. Cross-Cutting Requirements

| Area | Requirement |
| ---| --- |
| Tenancy | Three nested layers — tenant (the RLS wall) → profile → entity. Every row scoped by `tenant_id` always, plus `profile_id` and/or `entity_id` where relevant. |
| Auth | Supabase Auth, email OTP for v1. Session persisted in `expo-secure-store`. Recovery via email OTP. Biometric gate layered on app open and on sensitive modules. |
| Data access | The app talks to Postgres through the Supabase client governed by RLS — not a hand-rolled REST API. Server-side and scheduled work runs as Edge Functions. |
| Offline | TanStack Query persistence + expo-sqlite cache; optimistic writes queued and reconciled on reconnect, last-write-wins for a single user. |
| Notifications | Habit reminders, bill and restock alerts, routine prompts, schedule events, goal milestones (Expo push) — one inbox. |
| Privacy | Biometric lock on Spiritual Practice + Intimacy; RLS on all tables; no third-party data sale; export on demand. |
| Design | Afro-Futurist, dark base, goldenrod accents; every state (loading / empty / error); WCAG 2.1 AA; palette Night, Dark Green, Eminence, Spanish Orange, Goldenrod, Platinum, Sienna. |
| Performance (draft until measured) | Cold start < 3s · screen interaction < 100ms · sync/query p95 < 400ms · offline reads instant. |

Full detail in NFRs (3.3), Solution Architecture (5.1), and Security Architecture (5.10).

### 8\. User Experience & Design

*   **Key flow:** open → Command Center → see today → tap a do-now link → complete the Action. Capture is always one or two taps away.
*   **Design principle:** the number of taps to log, and whether a surface leads somewhere doable, are the primary design metrics.
*   **Links:** Hub Map (4.1), Wireframes (4.2), Design System (4.5), Brand & Visual Style Guide (4.6), Design Tokens (4.7).

### 9\. Scope

**In scope (v1):** the Command Center platform surface and four bounded contexts (Productivity, Lifestyle Vault, Academic HQ, Control Room), the shared spine, three-layer tenancy, scheduled automation, and the Notion data migration.

**Non-goals / out of scope (v1):**

*   No web client in v1 — Phase 7.
*   No AI insights layer in v1 — Phase 7.
*   No public commercial multi-tenant launch in v1 — **architecture ready; launch is Phase 7.**
*   **Not** a replacement for ClickUp as UJG's freelance task/time source of truth — the Control Room reads and rolls up.
*   No bank / Plaid auto-sync in v1 — manual entry plus recurring rules first.
*   No client-facing UJG product features. This is a personal + freelance operator OS.

### 12\. Release Criteria & Rollout

*   **Release criteria:** all in-scope hubs function on real migrated data; automation runs on schedule; the six-item failure chain passes; a real-device pass behind every slice.
*   **Rollout:** phased — 1 Spec & Architecture · 2 Foundation · 3 Build · 4 Polish · 5 Test · 6 Launch · 7 post-launch.
*   **Rollback:** EAS Update revert + safe Supabase migration down. Notion stays live until cutover verification passes.
*   **Kill criteria:** if after the one-week beta daily friction is **higher than Notion's**, stop and re-scope before adding modules.
