### 1\. Cadence Overview — Why This Is Not a Sprint Plan

This build does not run in two-week sprints with a team. It runs in **phases** gated by definitions of done, executed in **slices**.

| Field | Value |
| ---| --- |
| Unit of work | A slice — one build session's worth: one screen wired end to end, one migration, or one Edge Function |
| Timebox | Session-length, often 15–30 minutes, sometimes phone-only |
| Team | Omegea Hunter (owner, PO, reviewer) + Claude Code (build agent) |
| Sequencing rule | Work top to bottom. Don't skip phases. A phase is done only when its gate is met. |
| Tracking | ClickUp list `901110966415`; every slice references a `UJGFREE-####` custom ID in its commits |

### 2\. Goal

> Ship a sovereign Life OS one vertical slice at a time, never leaving a slice half-wired, until a full week of real life runs on the app and Notion is retired from daily use.

**Success looks like:** each phase gate met in order, with a real-device pass behind every completed ClickUp task.

### 3\. Capacity Model

| Resource | Role | Capacity | Focus factor |
| ---| ---| ---| --- |
| Omegea Hunter | Owner / PO / reviewer / device tester | Short anchored sessions, sometimes phone-only | Depth over duration |
| Claude Code | Build agent | One slice per session | Slices sized to fit one session |

There is no velocity number. The commitment unit is **one finishable slice**, not points.

### 7\. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
| ---| ---| ---| --- |
| Session slides into theming or refactors while core modules are unbuilt | High | High | Name it out loud and get back to shipping a slice |
| Slice left half-wired across sessions | Med | High | Definition of done forbids it; no session ends mid-slice |
| Ten empty screens scaffolded instead of one finished | Med | High | Vertical, not horizontal — finish Daily Command Center before starting Habit Tracker |
| Mock data merged into main | Med | Med | "No mock data left behind" is part of the definition of done |
| Migration data loss | Med | Critical | Idempotent scripts, run on a copy, verified row counts before cutover |

### 8\. Session Ritual (replaces ceremonies)

| Moment | Practice |
| ---| --- |
| Session start | State the task ID, the slice, and the definition of done |
| During | Commit at every working state — small commits, present tense, branch per feature, PR into `main` |
| Session end | Restate what's done and name the next slice |
| Task closure | Mark the ClickUp task complete only after a real-device pass |

### 9\. Definition of Done (per slice)

- [ ] Tables + RLS migration committed and applied
- [ ] Screen renders real data from Supabase (no mock data left behind)
- [ ] Create / read / update / delete paths work where the module needs them
- [ ] Loading, empty, and error states handled
- [ ] Works offline-read where the module is a daily-use surface
- [ ] Typed end to end (no `any` on data models)
- [ ] One manual pass on a real device before marking the ClickUp task complete
