### 1\. The MVP Definition Test

Everything on this page answers to one sentence.

> **v1 is complete when the app has been the sole daily Life OS for one full week — all in-scope modules functioning on real migrated data, automation running on schedule, and Notion retired from daily operation and kept as archive only.**

That is the test. Not a feature count, not a phase checklist, not a build that compiles. Seven consecutive days of real life run through the thing, with Notion closed.

Three things follow from stating it that way.

*   **The gate is usage, not shipping.** A build that installs and looks correct has proved nothing. The week is the proof.
*   **Real migrated data is part of the test.** An app that works on seed data and buckles on a year of actual records has not passed.
*   **Notion becoming an archive is the outcome, not a side effect.** If Notion is still open on day four because something is easier there, v1 is not done — and the reason is a defect, not a preference.

### 2\. Goals & Hypotheses

| # | Goal / hypothesis | How it is validated | Success signal |
| ---| ---| ---| --- |
| H1 | An owned application replaces the Notion Command Center for daily operation | Run the one-week beta with Notion closed | Seven straight days, no fallback to Notion for anything in scope |
| H2 | Capture friction is what killed the old system, and 1–2 tap logging fixes it | Tap counts on the built capture flows during the beta week | Habit, journal, and expense logging each land in 1–2 taps and stay habitual across the week |
| H3 | Real automation removes the remembering | Scheduled job run logs across the week | All five jobs fire with zero manual triggers and zero duplicates |
| H4 | Making every record type spawn an Action turns plans into execution | Schema audit plus completion volume | 100% of in-scope record types spawn Actions, and completions come from every context, not only Productivity |
| H5 | Sovereignty and privacy are achievable without enterprise machinery | Tenant isolation test and the sensitive-module gate test | Zero cross-tenant reads; nothing sensitive fetched, rendered, or cached before a fresh check |

*   **Primary objective of this release:** replace, not extend. The release exists to retire Notion from daily operation.
*   **Target audience:** one operator, one tenant, internal beta only. No external users in v1.

### 4\. Out of Scope — Not Planned

*   Client-facing UJG product features. This is a personal and freelance operator OS, not a client deliverable.
*   Replacing ClickUp as UJG's task and time source of truth. The Control Room reads and rolls up; it does not take over.
*   Any capability tied to Gatekeeper Sanctum — `PAUSED` indefinitely and not offered.
*   Multi-user collaboration inside one tenant beyond the owner and child profiles.

### 5\. Release Sequencing

Order is not preference here. Three sequencing constraints are real, and violating any of them creates rework.

**1\. Journal ships early in the Build phase — earlier than its hub's turn.** The Command Center links to today's journal entry, and the cockpit cannot ship with a card pointing at something that does not exist. Journal is therefore pulled out of the Lifestyle Vault sequence and built alongside the cockpit. Tracked as ClickUp task UJGFREE-14140.

**2\. Command Center plus the spine before any hub.** Every hub spawns Actions, writes Events, and reads the taxonomy. Building a hub before the spine means building its own private version of all three and then tearing it out. The spine is not a phase to get through — it is the thing every later phase depends on.

**3\. Then hubs vertically, one fully done before the next.** A hub is done when its records support full CRUD, spawn Actions, appear on the cockpit, and have every state handled. Half-finished hubs across four contexts is exactly the scope sprawl the risk register names, and it produces an app where nothing is trustworthy rather than an app where three things are.

| Order | Slice | Blocking reason |
| ---| ---| --- |
| 1 | Foundation — repo, Supabase, auth, RLS, tenancy scoping, design system | Nothing can be built correctly on top of missing tenancy or a missing design system |
| 2 | Spine — Actions, Events, days, notes, taxonomy | Every hub reads it |
| 3 | Command Center plus Journal | The cockpit is the product surface; the journal card is a hard dependency (UJGFREE-14140) |
| 4 | Productivity, fully | The daily execution surface, and the first proof the vertical-slice model works |
| 5 | Lifestyle Vault, fully | The largest context; nine sections over one bounded context |
| 6 | Academic HQ, fully | Smaller surface, real deadlines |
| 7 | Control Room, fully | Multi-entity money and work; depends on the money core being settled |
| 8 | The five scheduled jobs | Meaningful only once there are records to act on |
| 9 | Migration, run against a copy first | Needs the target schema complete |
| 10 | Polish, test, beta week | The definition test |

### 7\. The Thinnest Useful Version

The honest answer to "what is the smallest thing that would still replace Notion for a day."

| Included | Why it survives the cut |
| ---| --- |
| Command Center Today snapshot | Without it there is no reason to open the app |
| Quick capture | Without it nothing gets in |
| Actions with do-now links | Without it captured things do not lead anywhere |
| Days | The frame the snapshot reads |
| Notes | Where the thinking lands when there is nowhere else |
| The habit reset job | One piece of real automation, to prove the mechanism rather than the breadth |

**This is deliberately smaller than the stated MVP.** It is recorded as the fallback position if the phase model proves too slow — the version to ship and live in while the hubs are still being built, rather than waiting for all four contexts.

**And it would not meet G1.** A day is not a week, and a full week of daily operation touches money, meals, and kids. The thin version would carry a Tuesday. It would not carry seven consecutive days without Notion being reopened for something — which means shipping it alone would prove the mechanism and still leave the replacement claim unproved. It is a fallback, not a redefinition of the goal.

### 9\. Risks & Trade-offs

| Risk / trade-off | Impact | Mitigation | Owner |
| ---| ---| ---| --- |
| Scope sprawl across four contexts and many sub-trackers | Nothing finishes; the beta week never starts | Vertical slices, one hub fully done before the next; SHOULD items cut first | Omegea Hunter |
| The schema lock stays open | Build blocked at the foundation | Finish the hub-by-hub pass and append tables to 5.6 before Foundation completes | Omegea Hunter |
| Migration fidelity — a silently dropped source database | The beta week runs on incomplete data and the test result means nothing | Idempotent import, copy-first run, per-database row count verification before cutover | Omegea Hunter |
| Cutting the money core to reach the beta week faster | The week fails, because real life touches money daily | Money core is MUST and is not available to cut | Omegea Hunter |
| Building hubs before the spine to see visible progress sooner | Rework across every context | Sequencing constraint 2 is a hard rule, not a preference | Omegea Hunter |
| Tenancy correctness | A data leak, and a rewrite if retrofitted | RLS on every table from the first migration; the isolation test is a release gate | Omegea Hunter |

### 10\. Exit Criteria per Phase

A phase is not finished because its tasks are closed. It is finished when its exit criterion is demonstrable.

| Phase | Exit criterion |
| ---| --- |
| 1 Spec & Architecture | The spine, the schema, and the hub set are locked and written down; no table is still under discussion when Foundation starts |
| 2 Foundation | Auth works, RLS is on every table, the tenant isolation test passes, and the design system renders loading, empty, and error states |
| 3 Build | The Command Center plus each of the four contexts is fully done at core record level — full CRUD, Actions spawning, cockpit presence, all three states — with Journal shipped alongside the cockpit |
| 4 Polish | Every screen handles every state, the accessibility audit passes at WCAG 2.1 AA, and the Afro-Futurist pass is applied consistently |
| 5 Test | The failure chain passes, scheduled jobs survive a double-fire with zero duplicates, and the zero-row alert fires when a job's input is suppressed |
| 6 Launch | The migration has run against a copy with verified row counts, cutover is complete, and the one-week beta has been run as the sole Life OS with Notion closed |
| 7 Post-launch `FUTURE-STATE` | Tracked separately — web companion, AI insights, commercial release |

### 12\. Kill Criterion & Post-MVP Decision Framework

> **Kill criterion: if daily friction during the beta week is HIGHER than Notion's, stop and re-scope before adding a single further module.**

This is the one rule that overrides every other plan on this page. The failure mode it guards against is the seductive one — the app is nearly there, so the answer must be one more feature. It usually is not. If the thing is harder to use than what it replaced, more surface makes it worse, not better.

| Outcome | If the beta week shows… | Then… |
| ---| ---| --- |
| Persevere | Seven straight days, Notion closed, capture staying habitual | Cut over fully, archive Notion, and move to the SHOULD list and then post-launch |
| Re-scope | The week runs but friction is higher than Notion's in specific places | Stop adding modules. Fix the friction where it is, re-run the week, and do not proceed until it passes |
| Pivot the shape | The week fails because the phase model was too slow to reach a usable whole | Fall back to the Thinnest Useful Version (section 7), live in it, and grow outward from real use rather than from the plan |
| Stop | The week fails and friction is higher across the board, not in specific places | Halt the build. Re-scope from the definition test, not from the feature list |
